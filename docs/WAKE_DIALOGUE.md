# 本地唤醒与连续对话

SDK 产品可配置其他唤醒词及匹配资源，或关闭唤醒。以下描述默认云宝产品；同款设备的配置方法见 [SDK 指南](SDK.md)。

云宝使用 ListenAI SDK 0.1.6 的 ACOMP 单麦克风唤醒组件，在 AP 上检测“你好云宝”。模型和 wrap 配置从原机保留的 ROMFS 读取；固件检查文件边界、模型标识和单麦配置。不分发或重刷模型、AP 和资源。资源不兼容或初始化失败时保留按键对话，屏幕不会显示唤醒提示。

唤醒后提示音响起，屏幕进入“我在听”再说问题。录音、Impo 处理和回答仍使用官方 Gadget SDK。回答完成并等候 3 秒没有后续回复后，再次提示收音，可直接接着说。静音约 5 秒或短按主功能键退出连续对话，长按仍关机。一次说话最长 15 秒，网络失败或回复超时也会退出。诊断自测保持单轮。

默认云宝产品采用轮流说话：播放、下载回答和录音期间暂停本地唤醒，结束后留出 500 ms 尾音隔离。通用 Mini2 产品另通过 `wake_interrupt` 开启唤醒词打断：播放或等待回答时继续检测“小聆小聆”，命中后停止旧回答并提示重新收音；正在录音时暂停检测。必须先说唤醒词、等待提示音，再说新问题。回声处理使用原机右声道硬回采及官方 ACOMP，不把单纯提高麦克风灵敏度作为回声消除。

麦克风硬件由平台层统一管理。后台唤醒和对话任务共享已开启的音频流，对话回调独占优先；结束一轮录音仅移除对话回调，后台流继续运行。默认使用单声道；开启唤醒词打断时改用麦克风/回采双声道，前台仍只接收单声道麦克风。官方 AP 处理后的输出描述符始终归还，避免流阻塞。

单个 ADB 交互 shell 中的 `wake` 显示初始化、送帧、丢帧、触发计数、连续对话状态，以及打断启用状态、打断次数和非零回采帧计数。`wake off` / `wake on` 暂停/恢复本地检测，调试双声道 mic_test 前应先关闭唤醒。输出仅作诊断，不代替实物唤醒和听测。

主机测试执行真实 SDK 语音回合处理函数，覆盖两轮回答后自动收音、静音退出、按键中止不上传、TTS 失败退出及其他板型的单轮行为。另执行实际平台音频代码，检查回调独占、无重启切换、双声道冲突及启动失败回滚；资源解析测试覆盖边界、循环、坏头、坏 JSON 和关键词过滤。

2026-11-24 启动栈修正版已获用户确认：屏幕正常、能听到回答并继续对话。该轮使用官方直连回退路径；不能代表国内中继或长期稳定性通过。实机状态以 [验收记录](VALIDATION.md) 为准。网络响应仍可能等待数十秒，不能把收音结束后的等待当作唤醒失效。

## 网络选择

原 SDK 在启动时对全部已保存网络按无线信号排序。若先前测试过多个网络，重启后可能返回另一个网络，Wi-Fi 有 IP 仍可能无法完成 Impo TLS 握手。

`0006-remember-selected-network.patch` 在官方配网/手动连接成功后，仅额外保存优先 SSID。启动任务从官方 Wi-Fi 存储查找其原有凭据，先尝试连接并等待 DHCP；目标不存在或连接失败后启用原 SDK 自动连接。旧网络继续保留，不清除配对。不把 AP 的 BSSID 和频道固定为上次值。原生 `wifi connect` 改为等待实际连接结果，失败不覆盖优先选择。

主机测试执行实际 `net_wifi.c`，检查优先连接、缺失/失败回退、只在成功时保存、已经连接时选择更新，以及 shell 命令调用同一连接流程。驱动和 Impo 服务可达性仍需实机检查。
