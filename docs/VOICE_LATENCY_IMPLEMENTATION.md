# 语音延迟优化：第一阶段

基于 `447e107`，分支 `codex/voice-latency`。设计依据为 [VOICE_LATENCY_DESIGN.md](VOICE_LATENCY_DESIGN.md)。本阶段实现采集与上传解耦、回合关联、阶段查询及可配置端点；已在目标 Mini2 完成 60 次固定短问交错探索，结果与边界见验证记录。

## 已实现

- 保留最多 15 秒的完整 PSRAM 录音。采集任务只接收、做 VAD、追加 PCM；独立的 4 KiB 栈上传任务编码并通过官方 Link 请求队列发送。
- `batch` 使用精确 WAV 长度，采集结束后上传。实验 `overlap` 在确认有效语音后上传未知长度 WAV；只发送完整的 6144 字节编码块，封口后处理唯一末块及 JSON 结束标记。请求一旦开始，不自动改发批量请求。
- 用互斥量发布录音长度、封口和取消状态。上传任务退出之前不会复用录音区。满容量停止采集；丢样或采集异常终止该回合。
- 上传句柄保留到 ACK 或取消；Link 新增带调用方上下文的内部接口，旧接口仍可使用。排队以最多 20 ms 的等待片段检查取消，沿用原来的总预算；没有改动 TLS、Noise、WebSocket 的发送次序或共享实现。
- 回复带回合、订阅代次和父消息 ID。ACK 前的完整回复可暂存，ACK 后重新匹配；缺少关联、旧回合、旧订阅的回复不播报。最多四条待播回复、合计 16 KiB；超限明确失败。订阅中断结束当前回合，空闲后恢复订阅，不重发用户问题。
- 产品或回合间配置端点静音阈值 600～2000 ms，缺省 1200 ms；800 ms 仍属实验值。未更改 VAD 声学阈值；唤醒资源按用户后续要求单独更换，见下文。
- 屏幕显示“正在上传”“等待回复”“准备语音”“正在回答”“取消中”“语音失败”；“我在听”在后台上传期间继续保持。

## 配置与观测

SDK 通用缺省保持 `batch`、1200 ms，完整文字及原有播放缓冲。产品可增加：

```json
"voice": {"upload_mode": "overlap", "endpoint_pause_ms": 1200}
```

`products/arcs-mini2-latency-batch.json` 和 `products/arcs-mini2-latency-overlap.json` 使用相同的“小周小周”单麦克风唤醒资源，仅上传模式不同。资源从本地历史设备备份提取；其原 AP 分区与目标 Mini2 保留的 AP 逐字节一致，模型和 wrap 摘要写入 `resources/wake/xiaozhou-preserved.json`。构建仍校验资源，不能仅改标签替代声学模型。模型二进制不随仓库分发；实机资源安装、声音触发和在线结果见验证记录。上一轮部署 `overlap`、1200 ms 并通过重启短测；本轮较长输入回归失败后恢复普通 `batch`、1200 ms 产品。“小周小周”资源保留，`overlap` 继续作为显式实验选项。

构建元数据 `impo-sdk-build.json` 记录语音配置。应用可调用 `impo_arcs_mini_configure_voice()`、`impo_arcs_mini_voice_snapshot()`；配置只在空闲且连续会话已结束时接受。运行时配置不持久化，重启恢复产品默认值。

交互式 ADB shell：

```text
voice_latency
voice_latency batch 1200
voice_latency overlap 1200
voice_latency batch 800
```

`voice_latency` 分行输出设备单调时钟、阶段有效位、录音/排队/剩余字节、丢样和上传栈余量，避免 SDK shell 的定长格式化缓冲截断末尾。快照属于最近一轮；其中 `upload_overlap` 描述该轮，回合间配置成功则另行打印 `voice configured`。`queued_bytes`、`capture_end_backlog_bytes` 都按 WAV 原始字节计算，包含 44 字节头；不是 Base64 字节，也不代表底层发送或服务端接受。阶段编号如下：

| 编号 | 含义 |
| --- | --- |
| 0 | 最后有效语音帧在采集时间线的位置 |
| 1 | 采集结束 |
| 2 | 上传任务开始处理请求 |
| 3 | 全部请求体进入本地队列 |
| 4 | 可解析的成功 ACK |
| 5 | 与 ACK 匹配的完整消息到达 |
| 6 | 首笔 TTS 请求发起 |
| 7 | 本地回合取消 |

每轮 `voice_turn` 摘要仅含随机启动标识、代次、长度和时间，不含用户语音、回答正文或身份。补丁 `0018` 另输出 `speech_timing` 的首响应体字节、解码器首 PCM，以及 `sound_first_write` 的音频驱动首次接受写入，均带声音代次和设备单调时间；这些日志没有扩展上述快照。驱动写入不是 DMA 回调或声学首声。实际 DMA、底层首/末次 TX 及服务端分段追踪尚未接入，不能用“正在回答”状态代替声学测量。

## 验证边界

主机测试执行实际录音和上传实现，使用独立麦克风、采集、上传线程，以及真实互斥量。覆盖 6 秒/15 秒的缩放队列停顿、15 秒容量、跨块 Base64 解码后的全部 PCM、WAV 长度、无语音、采集超时、发送失败、取消、ACK 乱序、陈旧回调、队列超限、连续对话与唤醒打断。Link 测试执行实际槽位实现，覆盖上下文、旧接口、取消与槽位复用。主机结果不代表官方网关接受未知长度 WAV。

精确镜像、读回及物理验证结果记录于 [VOICE_LATENCY_VALIDATION.md](VOICE_LATENCY_VALIDATION.md)。本机已完成当前网关的完整请求、取消和不完整请求观察，以及固定短问声学对照；这些结果不自动代表其他网关、SDK 或全部语料。回退仅在回合结束后切回 `batch`，不自动重发未知结果的请求。

独立的协议负向检查应用、固定语料交错测试及 Mac 声学代理测量流程见 [测试工具说明](VOICE_LATENCY_BENCH.md)。诊断应用不进入普通固件；其额外订阅结束后，恢复并重启普通应用再做问答对照。

## 后续门槛

按句 TTS、TTS 预取和自适应起播尚未启用；需要稳定可播文字契约、请求上下文及快速音频 ingress，不能直接播放任意文字 delta。当前实现也没有承诺降低固定秒数或达到设计稿 P50/P95 目标。

此链路沿用 Impo `/tts`，本次不修改 TTS 或回答音色。按用户允许的替代方案使用已有兼容资源“小周小周”；未继续使用临时“小聆小聆”或“你好云宝”。本地旧“小飞小飞”候选未通过兼容验证，不能将小程序的角色名称或另一模型的误触发当作“小飞”支持。

模型头按实际 `ALOG_RES_HV100001` 完整校验，修复描述工具原先少一个零、运行时只校验部分前缀的问题。
